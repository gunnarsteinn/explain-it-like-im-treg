Dev, Test ogand Prod

Hvert eftirlit er til í þremur útgáfum, einni í hverju umhverfi. Þessar þrjár reglur segja þér hvaða útgáfa keyrir, á hvaða gögnum, og hvar frávikin lenda.

Every rule exists in three versions, one per environment. These three rules tell you which version runs, against which data, and where the exceptions end up.

  1. 01

    Að vista breytir Development

    Saving changes Development

    Þú vinnur alltaf í Dev. Þegar þú vistar verður til ný Dev-útgáfa. Það er aldrei deployað á Dev, vistunin er nóg.

    You always work in Dev. Saving creates a new Dev version. You never deploy to Dev; saving is enough.

  2. 02

    Deploy afritar Dev-útgáfuna yfir í Test eða Prod

    Deploy copies the Dev version to Test or Prod

    Test og Prod breytast ekki fyrr en þú deployar. Þangað til keyra þau áfram eldri útgáfuna.

    Test and Prod don't change until you deploy. Until then they keep running the older version.

  3. 03

    Keyrsla notar útgáfu og tengistreng þess umhverfis sem þú velur

    A run uses the version and connection of the environment you pick

    Í Run Task velurðu UAT. Prod-útgáfan keyrir alltaf á móti Prod-tengistreng data providersins og Test-útgáfan á móti Test-tengistrengnum. Frávikin verða til í sama umhverfi, svo Test-keyrsla býr til test-frávik.

    In Run Task you pick the UAT. The Prod version always runs against the data provider's Prod connection string, and the Test version against the Test one. Exceptions are created in that same environment, so a Test run produces test exceptions.

    Athugaðu: Run Task byrjar alltaf á Development. Skiptu um UAT ef þú ætlar að keyra Test eða Prod.

    Note: Run Task always starts on Development. Switch the UAT if you mean to run Test or Prod.

Svona tengist þetta

How it fits together

Útgáfa + tengistrengur = keyrslaVersion + connection = run

Hver lína er eitt umhverfi. Þegar þú keyrir velurðu eina línu með UAT, og bara sú lína keyrir.

Each row is one environment. When you run, the UAT picks one row, and only that row runs.

Then the Dev version ran against the Dev connection string. Prod wasn't touched. Run again with Production.

You don't need to redeploy the rule. The next Prod run uses the new connection string.

You can turn the Testing environment off there. Then there's only Dev and Prod, which is common.
